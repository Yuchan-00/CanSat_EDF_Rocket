### 2.3 P1 - NAV 시간 줄이기 (nlink 타이밍)

- NAV→FCU 전송은 72바이트입니다. 예전에는 NAV가 바이트마다 기다렸습니다. 이제 타이머(Timer3) 인터럽트가 바이트를 하나씩 보냅니다. 바이트 간격은 140 클럭입니다. 그동안 NAV는 다른 계산을 합니다.
- 전송 시간(SS 신호가 낮은 시간)은 벤치에서 618.44~620.56 µs입니다(M). 출처: `X/all_benches_nav_0.log`.
- 밀어내기 하한은 890 µs입니다. 실행기가 다시 계산한 값과 같습니다(890 = 890, M). 틱 사이 프레임 시각의 가장 큰 변화는 211.2 µs로, FCU의 시간초과 여유 600 µs 안입니다. 출처: `X/all_benches_nav_0.log`.
- 고정소수점 계산이 기준 모델과 같은지: 교차 검사에서 NAV 자세(쿼터니언) 최대 차이 7.82e-6입니다(한계 1e-4, M). AVR의 곱셈 함수와 C 함수를 20만 쌍 비교해 불일치 0입니다(M). 출처: `X/crosscheck.log`, `X/hosttest.log`.

### 2.4 W1 - 전송 감시 타이머

- NAV가 전송을 시작하면 타이머를 0부터 셉니다. 1000 µs가 지나도 전송이 안 끝나면 NAV가 전송을 끊습니다. 이 값은 `PROJ/params.json`의 `exchange_watchdog_us`입니다.
- 끊긴 전송은 FCU가 "프레임 하나 없음"으로 봅니다. FCU는 원래 있던 규칙(시간초과 틱)으로 넘어갑니다. NAV가 멈추지 않습니다.
- 부팅할 때 Timer3를 다른 코드가 바꾸지 않았는지 확인합니다. 바뀌었으면 NAV는 전송을 시작하지 않고 LED가 빠르게(약 16 Hz) 깜박입니다.
- 공동 시뮬레이션의 고장 주입(전송 중 인터럽트 하나를 지움): 감시 타이머 1번 작동, 프레임 1개 잃음, 비상정지 없음(M). 같은 고장을 감시 타이머 없는 펌웨어에 넣으면 I9 비상정지가 납니다(M, 설계대로의 대조 실험). 정상 비행 7개 실행에서 감시 타이머 작동 0번(M).
- 비용: NAV 틱→베인 최댓값 차이 0.0 µs, 프레임 전달 +0.9 µs(M, 한계 5 µs).
- 출처: `X/rows_summary.txt` (row18 cl_nl_lose_cmp, ol_nl_lose_cmp_now1, ol_nl_lose_cmp_w1, w1 quiet, row19), `fw09/impl/integ/ACCEPTANCE.md` 4절 row 18, row 19.

## 7. 실제 하드웨어 측정 계획 (체크리스트)

SPEC 11절의 측정입니다. **첫 동력 비행 전에** 모두 해야 합니다. 안전 절차는 `PROJ/docs/유선_시험비행_절차.md`를 따르세요.
모터를 돌리는 측정(2번의 기압계, 4번의 10분 호버)은 기체를 줄에 묶은 지상 시험으로 합니다. 자유 비행이 아닙니다. 어떤 이미지로 할지(비행 이미지 또는 지상 시험 빌드)는 담당자와 정하세요.

준비 (담당자에게 요청할 것):

- [ ] NAV에 시간 표시용 GPIO 핀을 켜는 측정용 빌드가 필요합니다. 이번 라운드에서는 만들지 않았습니다. 비행 이미지와 따로 만들고, 측정 뒤에는 비행 이미지(5장 해시)로 돌려놓습니다.
- [ ] 로직 분석기(8채널 이상), 오실로스코프, 멀티미터, 저울, 추력 측정대를 준비합니다.

측정:

- [ ] **1. nlink 파형** (로직 분석기, SS / SCK / MOSI / MISO)
  - 바이트 간격 139 클럭(약 8.7 µs) 이상, 바이트 사이 틈 75 클럭(약 4.7 µs) 이상인지 봅니다.
  - SS가 낮은 시간이 약 632 µs인지 봅니다(시뮬레이터 618~621 µs).
  - 10분 동안 멈춤이 없는지 봅니다. FCU 로그의 nlink 재동기·시간초과 수가 늘지 않아야 합니다(감시 타이머가 작동하지 않았다는 간접 증거).
- [ ] **2. NAV 시간** (GPIO 표시: 틱 시작, 계산 끝, SS 내림/올림, 루프 끝, 기압계 계산, 쉬는 시작)
  - 필수 작업(틱 시작 → FCU 응답)이 모든 틱에서 3200 µs 이하인지 봅니다. 시뮬레이터: 최대 2782.2 µs.
  - 계산 끝이 890 µs 하한과 어떤 관계인지 봅니다.
  - 바쁜 시간이 3800 µs 이하인지 봅니다.
  - 모터를 돌리는 동안 기압계 계산이 초당 49번 이상(목표 50)인지 봅니다. 시뮬레이터 값은 MS5611 드라이버의 값입니다. 산 부품은 BMP280이라 BMP280 드라이버(다음 제어 라운드)로 다시 재야 합니다.
- [ ] **3. 지연** (오실로스코프)
  - IMU 샘플(MPU 읽기 시작) → 베인 PWM 변화: 4.71 ms 이하(목표 4.5 ms 이하). 시뮬레이터: 최대 4.08 ms.
  - NAV 틱 → 베인: 4.0 ms 이하(목표 3.8 ms 이하). 시뮬레이터: 최대 3.58 ms.
- [ ] **4. 스택 여유** (10분 호버 뒤 칩 4개 모두)
  - FCU는 1024 B 이상이어야 합니다(시뮬레이터 1215 B). FCU는 로그의 1초 상태 기록에 스택 여유가 남습니다. NAV·GNS·COM은 읽는 방법을 담당자에게 확인하세요.
- [ ] **5. 센서 버스와 IMU 앞당김** (로직 분석기)
  - I2C 400 kHz에서 바이트당 22.5 µs인지 봅니다.
  - IMU 앞당김(타이머 미리 채우기)이 실제 칩에서 약 496 µs인지 봅니다(시뮬레이터 497.4~498.1 µs, `X/rows_summary.txt`; 칩 계산값 496.0 µs, `fw09/impl/integ/ACCEPTANCE.md` 4절 row 7).
- [ ] **6. 무게와 추력**
  - 캐리어 기판 무게를 잽니다(지금 50 g 가정값).
  - 구성마다 기체 무게를 잽니다(설계: 배터리 1647.2 g, 유선 1399.3 g, 하이브리드 1520.3 g, `PROJ/docs/SPEC.md` 머리말 v0.9 fix round).
  - 22.2 V에서 추력이 2.6 kgf 이상인지 추력 측정대로 잽니다.
- [ ] **7. 모터 회전 방향과 회전 관성**
  - EDF가 도는 방향을 확인합니다(반작용 보상 `ff_rotor_h_nms`의 부호, 지금 CW 가정).
  - 가능하면 회전체 관성도 측정대에서 잽니다.
- [ ] **8. ADC 2점 교정** (유선·하이브리드 빌드)
  - V_in, 전선 전압, 버퍼 전압을 멀티미터로 두 점(약 20 V, 25 V)에서 잽니다.
  - 값을 `PROJ/params.json`의 `power.adc_calibration_ASSUMED`에 넣고, 헤더를 다시 만들고, 다시 빌드합니다. 새 해시를 기록합니다.
  - 교정 전에는 유선 비행을 하지 않습니다(`PROJ/docs/유선_시험비행_절차.md` 4a).
